# TL;PR 0.3.2

## Changes

- Give body-only merge templates, such as a “🧾 Merge commit body” list, a conventional commit subject: the pull request title without its leading emoji, followed by `(#number)`. The template becomes the extended description. This matches how such pull requests are merged in practice, instead of GitHub's `Merge pull request #N from …` default
- Keep complete proposals unchanged: their subject fills **Commit message** exactly as written
- Strip emoji with variation selectors, skin tones, joiners and `:shortcodes:`, never a leading number

## Live merge form validation

On 2026-11-07 the helper ran on an open pull request in the Overview, against GitHub's real “Confirm merge” dialog:

- The commit message changed from GitHub's `Merge pull request #N from …` default to the conventional pull request title followed by `(#N)`
- The extended description changed from the emoji-prefixed pull request title to the exact bullet list of the “🧾 Merge commit body” comment
- Both values reached the state of GitHub's merge confirmation component, which is what a merge submits
- **Undo** restored both fields and that state; the dialog was then cancelled and the pull request stayed open and unmerged
- The controller detected the dialog opening on its own. The test browser was hidden, so its frame-based refresh ran once triggered manually; a visible Chrome tab runs it immediately
